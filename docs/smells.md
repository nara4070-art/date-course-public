# 코드 냄새 목록 — `src/index.ts`

대상: `date-course-public/src/index.ts` (로그인 없는 버전 API 서버).
코드를 읽기만 하고 정리했으며, 실행하거나 고치지 않았다. 줄번호는 작성 시점 기준이다.

## 동작·데이터에 영향을 주는 것

| 줄번호 | 무엇이 이상한지 | 그대로 두면 생길 일 |
|---|---|---|
| 417–418 | 주석은 "논리삭제(`del_yn = 'Y'`)"라고 하지만 실제로는 `DELETE`로 행을 물리적으로 지운다. `del_yn` 컬럼도 없다. | 주석을 믿고 "삭제해도 복구된다"고 판단하면 데이터가 영구 손실된다. |
| 253–426, 109 | 인증도 없고 Origin 검사도 없이 누구나 POST/PUT/DELETE를 할 수 있다. id는 목록 조회(56)로 전부 노출된다. 로그인 버전에 있는 cross-site 쓰기 차단도 없다. | 아무나, 또는 다른 사이트에 심어 둔 요청이 모든 기록을 수정하거나 지울 수 있다. |
| 90–102 | 주석은 "최근 30일치만 조회"라고 하지만, `from`/`to`가 없으면 조건 없이 전체를 반환한다. 개수 제한(LIMIT)도 없다. | 기록이 쌓일수록 응답이 커지고 느려진다. 30일 제한이 있다고 믿고 화면을 만들면 잘못 동작한다. |
| 110, 280 | `request.text()`로 본문 크기 제한 없이 전부 읽는다. | 아주 큰 요청이 들어오면 메모리와 CPU를 낭비하고, 워커 한도에 걸려 실패할 수 있다. |
| 234–235 | 주석은 "UUID 36자리"라고 하지만 실제로는 하이픈을 뺀 앞 12자(48비트)만 쓴다. INSERT에 충돌 처리도 없다. | 드물지만 id가 충돌하면 PK 위반으로 500 에러가 나고, 사용자는 원인을 알 수 없다. 주석을 믿고 다른 곳에서 36자로 검증하면 깨진다. |
| 236–244 | 주석은 "트랜잭션 처리"라고 하지만 트랜잭션이 없다. | 나중에 쿼리를 하나 더 붙이면서 원자성이 보장된다고 착각하면, 데이터가 반쯤만 저장될 수 있다. |
| 397–406 | 주석은 "수정자 ID도 같이 저장"이라고 하지만 저장하는 컬럼이 없다. | 누가 고쳤는지 추적할 수 있다고 믿게 된다. 감사나 분쟁 때 근거가 없다. |
| 433–434 | catch 블록 주석이 "여기는 안탐"이다. 실제로는 DB 연결 실패나 쿼리 에러가 전부 여기로 온다. | 이 블록을 "죽은 코드"로 보고 지우면, 처리되지 않은 예외로 응답 형식이 깨진다. |
| 43–46, 428–432 | 경로를 확인하기 전에 DB에 먼저 연결한다. | DB가 죽어 있으면 없는 경로 요청도 404가 아니라 500을 받는다. 쓸데없는 요청마다 DB 연결 비용이 든다. |
| 26, 441–446 | `ctx`를 받고도 쓰지 않는다. `db.end()`를 응답 전에 `await`하고 에러는 조용히 삼킨다. 로그인 버전은 `ctx.waitUntil`을 쓴다. | 응답이 연결 종료를 기다리느라 늦어진다. 종료 실패가 기록되지 않아 연결 누수를 알아챌 수 없다. |
| 49 | `/api/health`가 메서드를 확인하지 않는다. | POST/DELETE 등 어떤 메서드로도 응답한다. 사소하지만 다른 라우트와 규칙이 다르다. |
| 56, 109, 258, 428 | 지원하지 않는 메서드(예: `PATCH /api/courses`)가 405가 아니라 404 "지원하지 않는 요청"이 된다. | 클라이언트 쪽에서 "경로가 틀렸다"와 "메서드가 틀렸다"를 구분할 수 없어 디버깅이 어렵다. |

## 중복·구조

| 줄번호 | 무엇이 이상한지 | 그대로 두면 생길 일 |
|---|---|---|
| 109–248 / 278–414 | POST와 PUT의 본문 파싱과 검증 약 110줄이 복붙되어 있다. 279줄 주석이 "수정시 같이 고칠것!!"이라고 스스로 경고한다. | 한쪽만 고치면 등록과 수정의 검증 규칙이 달라진다. 등록은 막히는데 수정으로는 통과하는 데이터가 생긴다. |
| 61–88, 134–148, 302–316 | 날짜 검증 코드가 4번 반복된다(from, to, POST date, PUT date). | 형식을 바꿀 때 한 곳이라도 빠뜨리면 조회와 저장의 날짜 규칙이 어긋난다. |
| 179–224 / 345–388 | 장소와 먹거리 리스트 정리 로직이 4번 반복된다. 주석(202)이 "장소랑 똑같음"이라고 인정한다. | 제한값(100자, 30개)을 바꿀 때 4곳을 모두 고쳐야 하고, 하나를 놓치면 버그가 된다. |
| 93–95, 240–242, 264–266, 402–404 | SELECT/RETURNING 컬럼 목록 문자열이 4번 복붙되어 있다. | 컬럼을 추가하면 엔드포인트마다 응답 모양이 달라질 수 있다(목록에는 있는데 상세에는 없는 식). |
| 26–457 | 모든 라우트와 로직이 `fetch` 함수 하나(약 430줄)에 if/else로 들어 있다. | 어디를 고쳐도 전체를 읽어야 하고, 테스트도 함수 단위로 할 수 없다. |
| 30–36 | 모든 변수를 함수 맨 위에 `var`로 선언한다. `arr`, `s`, `i`, `d`, `ok`, `body` 같은 범용 이름을 여러 분기가 같이 쓴다. | 한 분기에서 남은 값이 다른 분기 로직에 섞여 들어가기 쉽다. 이름만 봐서는 용도를 알 수 없다. |
| 32, 448 | `flag`가 0/1/2 매직넘버이고, 2는 "사용안함"이다. 에러 상태를 `flag`, `resStatus`, `errMsg` 세 변수로 따로 관리한다. | 셋 중 하나만 바꾸는 실수(예: `flag=1`인데 `status`는 200)로 잘못된 응답이 나간다. |
| 35, 183 vs 349 | 같은 로직인데 POST는 `i`/`s`, PUT은 `j`/`tmp`/`tmp2`를 쓴다. | 복붙한 두 블록을 비교하기 어려워 차이를 찾기 힘들다. |
| 254 | `if` 조건 안에서 대입한다: `(arr2 = path.split("/"))`. | `==`를 잘못 쓴 것처럼 보여서 누군가 "고치면" 라우팅이 깨진다. |
| 1 | `// @ts-nocheck`로 파일 전체의 타입 검사를 끈다. 파라미터에 타입도 없다. | 오타나 잘못된 필드 접근(`env.HYPERDRVE` 등)이 배포 후 런타임에서야 드러난다. |

## 거짓이거나 낡은 주석·죽은 코드

| 줄번호 | 무엇이 이상한지 | 그대로 두면 생길 일 |
|---|---|---|
| 4–12 | 헤더가 "오라클 → MySQL 전환", "MySQL 5.7 기준(아마도)"라고 하지만 실제는 Postgres(`pg`, `::jsonb`, `to_char`)다. "함부로 수정하지 말것!!!"이라는 경고도 있다. | 새 사람이 MySQL 문법으로 쿼리를 쓰다가 깨진다. 경고 때문에 아무도 정리하지 못하고 냄새가 계속 쌓인다. |
| 17–22 | `VERSION`, `DEBUG`는 선언만 하고 쓰지 않는다. `DEBUG` 주석은 "true면 로그 출력"이라고 하지만 그런 코드가 없다. 주석 처리된 설정과 내부 IP(`192.168.0.15`)가 남아 있다. | `DEBUG=true`로 장애를 조사하려 해도 아무 일도 일어나지 않아 시간을 낭비한다. 내부망 정보가 코드에 노출된다. |
| 38 | "apache 에서 넘어오는거" — Apache가 없다(Cloudflare Workers의 정적 자산). | 배포 구조를 잘못 이해하게 된다. |
| 46 | "커넥션풀 사용" — 이 코드는 요청마다 `Client`를 새로 연다(풀링은 Hyperdrive가 함). | 코드 쪽에 풀이 있다고 믿고 연결 수 관련 판단을 잘못한다. |
| 60 | "날짜는 YYYYMMDD 형식" — 실제는 `YYYY-MM-DD`다. | 주석대로 `20261105`를 보내면 400이 난다. |
| 162 | `.trim()` 옆에 "XSS 방지" — trim은 XSS를 막지 못한다. 현재는 프론트엔드(`esc()`)가 이스케이프해서 안전한 것이다. | 서버가 막아 준다고 믿고 다른 클라이언트나 화면에서 이스케이프를 빼면 XSS가 생긴다. |
| 171 | "메모는 최대 500자" — 실제는 2000자다. | 주석과 코드 중 무엇이 맞는지 몰라 잘못 "고치게" 된다. |
| 194 | "최대 50개" — 실제는 30개다. | 위와 같다. |
| 245 | 주석 처리된 옛 코드(`// if (rs.rowCount == 0) ...`). | 의도를 알 수 없는 죽은 코드가 계속 남는다. |
| 452 | "XML → JSON 변경됨" — 이력 주석이 코드에 남아 있다. | 의미 없는 잡음이 늘어나고, 이력은 git에서 봐야 할 정보다. |
| 198, 221, 363, 385 | 메시지가 "장소 은(는)"처럼 템플릿을 그대로 복붙한 어색한 조사로 되어 있다. | 사용자에게 어색한 문구가 그대로 보인다. |
